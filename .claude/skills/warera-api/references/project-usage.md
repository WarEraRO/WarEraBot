# Project usage: procedure → client method → callers

Since 2026-11-02 every WarEra call goes through the `warera` client package (`warera/README.md`); the bot's instance is `utils.api.warera`. Find the method and callers of a procedure with `tools/agent-cli proc <procedure>`, and re-grep before relying on caller lists: `rg -n "warera\." cogs utils run.py`.

## Infrastructure (`warera/`)

| Piece | Role |
|---|---|
| `utils/api.py` | Creates the bot's `WarEraClient(api_key=config['api'])` (env `WARERA_API_KEY`, `config.py:13`). `run.py` awaits `warera.close()` on shutdown. |
| `warera/transport.py` | One lazily created `aiohttp.ClientSession`; `X-API-Key` added **per request** (not a session default). GET only. Retries 429 (Retry-After), 5xx and network errors with jittered backoff (5 attempts, max 60 s); 60 s timeout per attempt; at most 10 requests in flight; pauses while `ratelimit-remaining` is 0. Raises the `warera.exceptions` hierarchy. |
| `warera/batching.py` | tRPC batching: dedup, chunks of 50 calls / ~7000 URL chars sent concurrently, per-item results (207 slot errors), 5xx slots re-sent. `Coalescer` merges calls started in the same event-loop iteration into one request. |
| `warera/cache.py` | Single-flight dedup of identical in-flight calls; TTL cache only for `DEFAULT_CACHE_TTLS` (`gameConfig.getGameConfig` 1 h, expired copy served when a refresh fails). |
| `warera/endpoints/*.py` | The methods below. They return `None`, or a dict without the failed keys, and never raise (`@guarded`). |
| `warera.users.username_ids` | Process-lifetime `username → userId` cache used by `find_by_name`, `find_many_by_name` and `ids_by_name`, with no TTL. |
| `cogs/commands/fight_status.py:fight_status_from_user` | Builds the `/fightstatus` row from a `getUserLite` result already fetched (no request); moved out of the API layer. |

**Every per-member/per-country loop in `cogs/` uses the batched `*_many` methods (since 2026-10-12).** Concurrent unrelated calls (`asyncio.gather`) are coalesced too: in the equivalence harness `/top_user_weekly_donations` went from 269 to 58 HTTP requests and the MU weekly report from 94 to 52, with identical output **[project, 2026-11-02]**.

**No other HTTP client talks to WarEra.** `cogs/tasks/reddit_monitor.py` has its own key-less session (`RedditMonitorJob._get_session()`, closed in `cog_unload`); it used to reuse the WarEra session and leaked the key to reddit.com. **[project]**

## Duplication and possible issues

Fixed on 2026-11-02 by the `warera` client: the six copy-pasted pagination loops (now `Endpoint._collect` / `_collect_since`), inconsistent signatures (`session` first, raw envelopes), raw URL building in `damage.py` and `tests/calc-damages.py`, expected 404s logged as errors, and eight per-cog gameConfig caches. Still open:

1. **Per-cog caches** of `getAllCountries` with different TTLs (300 s to 24 h) and derived maps. There's no shared country cache; caching it centrally would need a TTL every caller accepts.
2. `warera.users.find_by_name` relies on Discord display name == WarEra username, and `username_ids` never expires (renames go stale).
3. **Stale rows:** the `event.getEventsPaginated` (`get_events`) and region `upgrade.getUpgradeByTypeAndEntity` (`get_region_upgrades`, `region_upgrades.py`) entries above describe code that isn't in the current tree (only a `.pyc` remains). Verify before relying on them.
