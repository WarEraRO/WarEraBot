# Guide-article audit ledger (English, category Guide)

> Every in-game article with **category `guide`** and **language `en`**, as of **2026-10-27**, and what this skill did with it.
> Registry source `GUIDE_ARTICLES`. Open this page for provenance questions ("did we read guide X?", "why isn't Y in the
> skill?"); for game rules use the topic files.

## How the set was built

- **Enumeration**: `article.getArticlesPaginated {type: "last", limit: 100, categories: ["guide"], languages: ["en"]}`, 7 pages
  until `nextCursor` was empty: **666 articles**, no duplicates. **Cross-check**: the same call without `languages` returned
  1,717 guide articles in all languages (ar 316, es 150, de 104, pt 97, it 76 …), whose `en` items are exactly the same 666 ids,
  and no item outside category `guide`. So the filters really filter, and the set is complete for that date.
- **Retrieval**: `article.getArticleById` for each id, **666 of 666 fetched in full**, 0 failures. On the full object every
  article has `category: "guide"` and `language: "en"`, `isPublished: true`, `isDeleted: false`. Published 2025-05-02 →
  2026-10-27 (game versions v0.15 → v0.27.1).
- **Fixed for every row**, so not repeated per row: category `guide`, language `en` (both confirmed on the full fetch); URL
  `https://app.warera.io/article/<Article ID>`; **Published** = `publishedAt`. **No modification date is recorded**: the API's
  `updatedAt` moves when an article is viewed (see the `warera-api` skill), so it can't date an edit, and the API exposes no
  edit history. A few authors write their own edit dates in the text; those are in the notes.
- **Images were listed but not OCR'd.** Many guides keep their tables in screenshots; a guide whose content is only in images is
  marked so. This is the main limit of the review.

## Review depth (column "Review")

| Value | What was done |
|---|---|
| full | whole text read and compared claim by claim with the skill |
| claims | every line with a number, formula or rule word extracted (up to ~2,000 characters), each claim compared with the skill |
| claim skim | the first ~330 characters of such lines read; enough to classify the article, not to check every claim |
| opening skim | title and the first ~150 characters; used only for articles with no game content |
| full (earlier session) | already ingested on 2026-10-25/26 (BUHDEUCE, V027_GUIDES) |

A "consistent where skimmed" or "excluded: generic advice" row means no contradiction was **seen** at skim depth, not that every
claim was verified.

## Validity (column "Validity")

verified current · historically valid (true for a past version) · superseded · partially valid (some parts current, some not) ·
unverified · contradicted (conflicts with stronger evidence) · n/a (no mechanics) · consistent where skimmed.

"Temporal context" is `known` when the article names its version, else `approx: under vX` = the patch in force on its
publication day (from [data/patch-history.yaml](../data/patch-history.yaml)). "Later patches" lists the patches after
publication that touch the article's main topics, i.e. the ones that may have outdated it.
